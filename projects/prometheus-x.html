CASE STUDY / 02 ENVIRONMENTAL MONITORING / SOFTWARE

Prometheus X

Software for connected environmental monitoring, designed to present hardware data through a clear interface and controlled access.

MY ROLE Frontend and backend software
STATUS In development
BASED Pokhara, Nepal
PROJECT INTERFACE FIG. 01 / OVERVIEW

PROJECT NOTES

The work is more than a screenshot. It is a set of decisions about structure, clarity, and how different parts of an experience fit together.

Prometheus X is in development. The hardware is built by a teammate; Prabin’s role is frontend and backend software. No fire prediction or verified live telemetry is claimed.

01 /

The idea

Prometheus X is an environmental monitoring project that connects hardware measurements with software for viewing and handling incoming data. The goal is to make information easier to understand through a considered interface and access appropriate to different users.

The project is in development. The interface work is presented as software progress, not as proof of live deployment, reliable field telemetry, or environmental outcomes.

02 /

My contribution

I work on the software frontend and backend. My teammate is responsible for the hardware. This case study focuses on the software experience and the way the interface organizes the system.

That separation matters: the software needs to communicate the project clearly while respecting the actual state of development and not exposing restricted operational detail unnecessarily.

03 /

Designing around access

The project separates the public-facing experience from authorized and administrative workflows. That distinction helps the public understand the project without treating every visitor as someone who should access restricted areas.

The supplied screens show separate access paths, including authorized login and admin login. Access control is a design and implementation concern, not merely a visual detail.

04 /

Clarity and system context

The public information and technology screens provide context for what the project is and how its components relate. A useful interface should help someone understand the system without implying that every planned capability is already operational.

The architecture and access-related screens also help communicate that this is a system with multiple parts, rather than a single landing page.

05 /

Current scope and next steps

Prometheus X remains in development. No fire-prediction capability, verified live sensor readings, deployed reliability, or measured environmental impact is claimed here.

As development progresses, the next useful step is to document implemented workflows against the actual system state, keep access boundaries clear, and present live data only when it can be verified.
